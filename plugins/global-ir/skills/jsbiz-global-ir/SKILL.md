# jsbiz-global-ir — 국문 IR 덱 → 해외 데모데이 영문 덱 재구성

정석Biz(이동건)의 영어 IR 강의·멘토링 방법론을 코드로 옮긴 스킬이다.
핵심 철학: **번역이 아니라 재구성**. 국내 지원사업용 덱(개발계획·조직도·ESG 중심)을
해외 심사역이 3분 안에 이해하는 스토리(문제→해결→증거→Ask)로 다시 짠다.

## 산출물 (항상 3종)

`{YYYY.MM.DD}_{회사명}_{타깃}_영문IR/` 폴더에:
1. `{회사명}_GlobalIR_EN_v1.pptx` — 영문 10장, 16:9, **발표자 노트에 슬라이드별 영어 스크립트**
2. 같은 이름 `.pdf` — 공유·인쇄용
3. `재구성가이드.md` — 한국어. 슬라이드 매핑표 / 영어 스크립트 전문 / 예상 Q&A 6~8개 / **[확인 필요] 목록**

## 환경 준비 (최초 1회)

```bash
pip install python-pptx pymupdf pillow
```
Node/npm 불필요. 렌더 검수는 MS Office(Windows) 또는 LibreOffice가 있으면 자동, 없으면 텍스트 검수로 대체.

## 워크플로 (6단계)

### ① INTAKE — 입력 확인
필요 정보가 빠져 있으면 **한 번에 묶어서** 질문한다(여러 번 되묻지 않기):
- 원본 덱 파일(PDF/PPTX) / 타깃 국가·행사명 / 발표 시간(기본 3분) / 청중(데모데이·VC·정부) / Ask 유형(파트너·투자·둘 다)
- 발표 언어는 기본 영어. 목차는 아래 표준 10장(사용자가 별도 목차를 주면 그것을 따르되 슬라이드 타입은 라이브러리에서 매핑)

표준 10장: ①표지 ②회사 업력 ③주력 제품(1개) ④문제(타깃 시장 맥락) ⑤기존 솔루션 한계 ⑥해결/기술(가볍게) ⑦트랙션(한국 성과) ⑧타깃 시장 진출 전략 ⑨Ask ⑩팀

### ② ANALYZE — 원본 판독
- PDF는 Read 도구로 페이지를 나눠 읽고(10p 초과 시 pages 필수), PPTX는 `markitdown`으로 텍스트 추출.
- **사실 인벤토리**를 만든다: 매출·성장률·인증·특허·실증·고객·팀 — 각 항목에 "원본 몇 페이지, 출처 표기 유무"를 기록.
- 이 인벤토리가 이후 모든 카피의 유일한 사실 원천이다.

### ③ EXTRACT — 증거자산 추출
```bash
python scripts/extract_assets.py 원본.pdf -o assets_out          # 임베디드 이미지 + 컨택트시트
python scripts/prep_assets.py crop in.png out.png --box 78,96,0,0  # 한글 캡션 밴드 제거(위,아래,좌,우 px)
python scripts/prep_assets.py round in.png out.png --radius 28     # 모서리 라운딩
python scripts/prep_assets.py whiten logo.png logo_white.png       # 다크 표지용 흰색 로고
python scripts/prep_assets.py strip out.png --inputs a.png b.png   # 로고 월 병합
```
- `_contact_sheet.png`를 **Read 도구로 열어 눈으로 식별**하고, 어떤 파일이 무엇인지(제품 렌더/인증서/실증 사진/로고) 메모한다. 파일명만 보고 추측하지 말 것 — 이번 파이프라인에서 가장 흔한 실수가 엉뚱한 사진 배치다.
- 한글 텍스트가 박힌 이미지는 크롭하거나 제외한다(영문 덱에 한글 잔존 금지). 크롭 결과는 반드시 다시 열어 확인.

### ④ COMPOSE — deck_spec.json 작성
**먼저 `references/pitching-principles.md`를 읽는다** (화법·구성 원칙 전체).
슬라이드 구성은 `references/slide-library.md`의 10개 타입에 매핑하고, 타깃 국가 파일이 있으면
`references/country-notes/{국가}.md`도 읽는다. 테마는 `references/themes.md`에서 업종에 맞게 1개 선택(기본 ocean).

스펙 작성 시 지켜야 할 **팩트 가드레일** (이 스킬의 신뢰성의 핵심):
1. 원본에 없는 숫자·사실을 만들지 않는다. 비어 보이는 슬라이드는 정성 문구로 채우고, 필요한 숫자는 가이드 MD의 [확인 필요]에 올린다.
2. **원본 차트 이미지는 제목·출처를 원문과 대조한 뒤에만 재사용**한다. 불일치하면(실제로 무관한 산업 차트가 붙어 있는 덱이 있다) 원본 텍스트의 수치로 네이티브 차트를 새로 그린다.
3. 시장 수치에는 출처를 병기한다. 타깃 국가의 정책·규격은 실재가 확실한 것만 쓴다.
4. 밸류에이션·라운드명은 쓰지 않는다. Ask는 금액 대신 outcome("end-2027: 인증 완료·N개 실증·첫 계약")으로.
5. 사람 이름 로마자, 제품 영문명은 확정 정보가 아니면 [확인 필요]에 올린다.

발표자 노트(notes)에는 슬라이드당 3~5개 단문으로 스크립트를 쓴다. 전체 분량: 발표시간 1분당 약 140단어.

### ⑤ BUILD — 덱 생성
```bash
python scripts/build_deck.py deck_spec.json
```
스펙 형식은 `assets/spec.example.json`(주석 대신 실동작 예시)과 `assets/spec.schema.json` 참조.
이미지 경로는 스펙의 `assets_dir` 기준 상대경로. 아이콘은 `assets/icons/`의 이름을 스펙에 적으면 테마 색으로 자동 틴팅된다.

### ⑥ QA — 렌더 검수 (필수, 건너뛰지 말 것)
```bash
python scripts/render_qa.py deck.pptx -o qa_png --pdf
```
`references/qa-checklist.md`의 항목대로 **모든 슬라이드 PNG를 Read 도구로 열어** 확인한다.
가장 흔한 결함 4가지: 텍스트 오버플로/겹침, 엉뚱한 이미지 배치, 차트 데이터 라벨 반올림 오류, 이미지 속 한글 잔존.
수정 후에는 바뀐 슬라이드만 `--slides N M`으로 재렌더해 재확인한다. 렌더러가 없는 환경이면
`markitdown deck.pptx`로 텍스트 검수 후 "PowerPoint에서 직접 확인 필요" 항목을 가이드에 명시한다.

## 가이드 MD 구성 (항상 이 순서)

1. 슬라이드 매핑표 (새 10장 ← 원본 페이지/자산)
2. 적용한 피칭 원칙 요약 (5~10개, 근거와 함께)
3. 영어 스크립트 전문 (노트와 동일 내용)
4. 예상 Q&A 6~8개 — 반드시 포함: "Who exactly is your customer?", "Who would buy your business?"(Exit), 현지 경쟁·인증 질문, 빅테크 진입 질문
5. **[확인 필요] 목록** — 로마자 표기, 행사명, 인증 체계, 미확인 수치 등
6. 발표 연습 팁 (단문 소리내어 연습, 분량 실측, 암기 티 금지)

## 하지 말 것

- 원본 20장을 순서만 바꿔 20장으로 내놓는 것 — 데모데이 기준으로 KPI표·추진일정·조직도·ESG·특허 전체목록은 **빼고**, 원본 덱을 Q&A용 Appendix로 지참하라고 안내한다.
- 슬라이드에 5줄 넘는 문단, 불릿 7개 초과(단기기억 한계), 장식용 수상 로고 나열.
- 렌더 QA 없이 "완성" 선언. 스펙이 빌드됐다는 것과 슬라이드가 멀쩡하다는 것은 다른 문제다.
